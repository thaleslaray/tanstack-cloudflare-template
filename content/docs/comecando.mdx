Este guia leva você de zero até o template rodando no seu computador, com banco de dados e login funcionando. Nada aqui usa a nuvem: tudo roda local.

## O que você precisa ter

- **Node.js 22 ou mais novo.** Confira com `node -v`.
- **npm**, que já vem junto com o Node.
- **git**, para clonar o repositório.
- Um terminal e um editor de código.

Você não precisa de conta na Cloudflare para rodar localmente. A conta só entra na hora de publicar (veja a página de deploy).

## Baixe o projeto

Clone o repositório e instale as dependências:

```bash
git clone <url-do-seu-repositorio> meu-app
cd meu-app
npm install
```

Avisos do `npm install` (como `peer dependency`) pode ignorar; só mensagens de erro importam.

## Crie o arquivo de segredos locais

Os segredos ficam em um arquivo chamado `.dev.vars`, que **nunca vai para o Git**. Copie o modelo:

```bash
cp .dev.vars.example .dev.vars
```

Abra o `.dev.vars` e troque o valor de `BETTER_AUTH_SECRET` por uma sequência longa e aleatória. Você pode gerar uma com:

```bash
openssl rand -base64 32
```

No Windows, sem `openssl`:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

O segredo precisa ter 32 caracteres ou mais.

As outras chaves (Resend, Google, GitHub) são opcionais no seu computador. Sem elas o template continua funcionando: os e-mails aparecem no terminal em vez de serem enviados (isso só vale no localhost; em produção é preciso um provedor de e-mail). O login com senha é opcional e vem desligado: `PASSWORD_LOGIN_ENABLED=true` no `.dev.vars` liga.

## Crie as tabelas do banco

O banco local é um D1 simulado, guardado na pasta `.wrangler/state`. Aplique as migrations:

```bash
npm run db:migrate:local
```

Faça isso uma vez, e de novo sempre que você criar uma migration nova.

## Rode o app

```bash
npm run dev
```

Abra `http://localhost:3000`. Se a porta 3000 estiver ocupada, rode `npx vite dev --port 3001` e acrescente `BETTER_AUTH_URL=http://localhost:3001` no `.dev.vars`.

Com o app rodando, `http://localhost:3000/cdn-cgi/local/explorer` abre um painel com o banco, os arquivos e os logs de cada requisição.

## Faça o primeiro login

Entre em **Entrar** e escolha o login por código. Digite seu e-mail e envie.

Como você ainda não configurou um serviço de e-mail, **o código aparece no terminal** onde o `npm run dev` está rodando, dentro de uma mensagem de e-mail simulada. Copie os seis dígitos, cole no formulário e pronto: você está logado, e você cai no painel (`/app`). Nome, foto e encerramento de conta ficam em `/app/configuracoes`. As demos em `/demo/*` só existem no `npm run dev`.

## Usando o Claude Code

Se você usa o Claude Code, abra a pasta do projeto e rode:

```text
/setup
```

O comando conversa com você, confere os pré-requisitos, cria o `.dev.vars`, aplica as migrations e sobe o servidor. O arquivo `AGENTS.md` na raiz (o `CLAUDE.md` aponta para ele) do projeto explica ao Claude as regras do template (por exemplo, que a configuração fica em `wrangler.jsonc` e que o CLI `cf`, ainda em beta, fica de fora por enquanto), então ele já começa sabendo o que pode e o que não pode fazer.

## Se algo der errado

- **O `npm run e2e` falha com porta ocupada:** ele precisa da porta 3000 livre (não rode junto com o `npm run dev`); ou use `E2E_PORT=3001 npm run e2e`. Na primeira vez rode também `npx playwright install chromium`.
- **A porta está ocupada:** use `npx vite dev --port 3001` (e o `BETTER_AUTH_URL` no `.dev.vars`, como acima).
- **Erro de tabela inexistente:** rode `npm run db:migrate:local` de novo.
- **Tipos dos bindings desatualizados:** rode `npm run typecheck`, que regenera os tipos antes de checar.
