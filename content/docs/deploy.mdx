Publicar é trocar três coisas locais por coisas reais: um banco D1 de verdade, a URL pública e os segredos. Siga a ordem abaixo. Todos os comandos usam o **Wrangler**, o CLI estável da Cloudflare, que já vem instalado no projeto.

<aside>

**Versões fixadas.** O `wrangler` e o plugin do Vite para Cloudflare estão fixados no `package.json` (sem `^`). Não atualize por impulso: leia o changelog e rode `npm run typecheck`, `npm run build` e `npx wrangler deploy --dry-run` antes de confiar numa versão nova.

</aside>

## 1. Entre na sua conta

```bash
npx wrangler login
```

Isso abre o navegador para você autorizar o Wrangler. `npx wrangler whoami` confirma em qual conta você entrou.

## 2. Crie o banco D1

```bash
npx wrangler d1 create meu-app-db
```

O comando mostra um trecho de configuração com um `database_id`. Guarde: ele identifica o banco.

## 3. Cole o ID no `wrangler.jsonc`

O template vem com `"database_id": "REPLACE_ME"` dentro de `d1_databases`. Troque `REPLACE_ME` pelo ID real (e `database_name` pelo nome que você usou). É só esse lugar: os scripts de migração usam o nome do binding, `DB`.

Depois da troca, rode `npm run db:migrate:local` de novo: o banco local também é identificado por esse ID.

## 4. Crie o bucket de arquivos (R2)

```bash
npx wrangler r2 bucket create tanstack-cloudflare-template-files
```

Use o mesmo nome que está em `bucket_name`, no `wrangler.jsonc`.

## 5. Aplique as migrations no banco remoto

```bash
npm run db:migrate:remote
```

## 6. Ajuste a URL pública

No `wrangler.jsonc`, dentro de `"vars"`, troque o valor de `BETTER_AUTH_URL` pela URL em que o app vai viver, por exemplo `https://meu-app.seudominio.com.br`. O login usa esse endereço para montar links e cookies, então ele precisa estar certo.

## 7. Teste sem publicar

```bash
npm run build
npx wrangler deploy --dry-run
```

O resultado lista os bindings que o Worker vai receber: `COUNTER`, `DB`, `BUCKET`, `PUBLIC_RATE_LIMIT` e `BETTER_AUTH_URL`.

## 8. Publique com os segredos

Crie um arquivo só com os segredos de produção, `.prod.vars` (ele não vai para o Git), com os mesmos nomes do `.dev.vars.example`, e publique:

```bash
npm run deploy -- --secrets-file .prod.vars
```

O arquivo precisa ter pelo menos `BETTER_AUTH_SECRET`. Use um valor **diferente** do local.

Prefere subir os segredos separado do deploy? `npx wrangler secret bulk .prod.vars` manda todos de uma vez, e `npx wrangler secret put BETTER_AUTH_SECRET` manda um (ele pergunta o valor). Os segredos ficam guardados no Worker: nos próximos deploys basta `npm run deploy`.

## O botão Deploy to Cloudflare

O `README.md` tem um botão **Deploy to Cloudflare**. Quem clica nele clona o repositório para a própria conta e publica o Worker. Na tela de configuração, use `npm run build` como comando de build e `npx wrangler deploy` como comando de deploy. O banco, a URL pública e os segredos continuam sendo os passos acima.

## Depois do deploy

- Abra a URL publicada e faça um login de teste.
- Confira os logs no painel da Cloudflare (a observabilidade já está ligada no `wrangler.jsonc`) ou ao vivo com `npx wrangler tail`.
- Configure um provedor de e-mail (Resend ou o Cloudflare Email Service). Sem isso, o código de login só aparece nos logs, e seus usuários não conseguem entrar.
