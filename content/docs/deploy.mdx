Publicar é trocar três coisas locais por coisas reais: o banco e o bucket de verdade, a URL pública e os segredos. Todos os comandos usam o **Wrangler**, o CLI estável da Cloudflare, que já vem instalado no projeto.

<aside>

**Dependências.** O `package.json` usa `^` (versões menores sobem sozinhas) e o `package-lock.json` é versionado: quem clona recebe o que está no lock. O Dependabot abre PRs semanais; leia o changelog do `wrangler` e confira o CI (`typecheck`, `build`, `wrangler deploy --dry-run`) antes de mesclar.

</aside>

## Antes de tudo: a URL pública no SEO

Em `src/config/app.ts`, troque `url` pela URL pública (por exemplo `https://meu-app.seudominio.com.br`) **antes do build**. Ela entra no sitemap, no canonical e no `og:url`. Com `localhost`, o `npm run sitemap` avisa.

## 1. Entre na sua conta

```bash
npx wrangler login
```

Isso abre o navegador para você autorizar o Wrangler. `npx wrangler whoami` confirma em qual conta você entrou.

## 2. Banco e bucket: criados sozinhos

O `wrangler.jsonc` não tem `database_id` (D1) nem `bucket_name` (R2) de propósito. Pela documentação da Cloudflare, o Wrangler cria esses recursos no primeiro `wrangler deploy` (provisionamento automático), com o nome do Worker como prefixo. Você não roda `d1 create` nem `r2 bucket create`.

Já tem um banco D1 seu? Acrescente `"database_id": "<id>"` no binding `DB`.

## 3. Crie os segredos de produção

Crie `.prod.vars` (não vai para o Git) com os nomes do `.dev.vars.example`:

- `BETTER_AUTH_SECRET`: **obrigatório**, um valor diferente do local, com 32 caracteres ou mais (`openssl rand -base64 32`; no Windows, `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`).
- `RESEND_API_KEY` e `EMAIL_FROM`: **recomendados**. Em produção, sem provedor de e-mail o login **recusa enviar** o código (o envio só vai para o terminal no localhost).
- `GOOGLE_*` e `GITHUB_*`: opcionais (cada provedor liga só com o par id + segredo).
- `PASSWORD_LOGIN_ENABLED=true`: opcional. O login com senha vem desligado.

`BETTER_AUTH_URL` é opcional: a URL do app vem da requisição. Para fixar uma URL, defina `BETTER_AUTH_URL` como segredo.

## 4. Primeiro deploy

```bash
npm run build
npx wrangler deploy --dry-run
npx wrangler deploy --secrets-file .prod.vars
npm run db:migrate:remote
```

O `--dry-run` lista os bindings (`COUNTER`, `DB`, `BUCKET`, `PUBLIC_RATE_LIMIT`). O `deploy` cria o banco e o bucket e publica; só então dá para migrar o banco, por isso `db:migrate:remote` vem depois.

## 5. Deploys seguintes

```bash
npm run deploy
```

O `predeploy` aplica as migrações no banco remoto **antes** do build e da publicação, então a tabela nova já existe quando o código novo sobe. Os segredos ficam guardados no Worker; use `-- --secrets-file .prod.vars` só quando mudar algum. Prefere subir segredos à parte? `npx wrangler secret bulk .prod.vars`, ou `npx wrangler secret put NOME` (um por vez).

## Banco rápido, em qualquer lugar do mundo

O banco D1 fica numa região só, e cada consulta de um Worker distante atravessa o caminho até ela. O template já liga o **Smart Placement** (o Worker roda perto do banco) e usa a **Sessions API** do D1. Para leituras ainda mais rápidas, ligue a **Read Replication** no painel da Cloudflare: **D1, o seu banco, Settings, Enable Read Replication**. É opcional: sem ligar, tudo continua funcionando, só vai ao banco principal.

## O botão Deploy to Cloudflare

O `README.md` tem um botão **Deploy to Cloudflare**. Segundo a documentação da Cloudflare, ele clona o repositório para a sua conta do GitHub/GitLab, deixa você escolher os nomes na tela de configuração, e compila e publica com o **Workers Builds**, criando e ligando os recursos (aqui: o Worker, o banco D1, o bucket R2 e o Durable Object).

Na tela de configuração:

- **Build command:** `npm run build`
- **Deploy command:** `npx wrangler deploy && npx wrangler d1 migrations apply DB --remote`. A Cloudflare usa `npx wrangler deploy` por padrão e permite trocar. A migração vai depois porque o banco só existe depois do primeiro deploy; por isso não use `npm run deploy` aqui (ele migra antes).
- **Segredos:** a tela lê o `.dev.vars.example` e as descrições em `cloudflare.bindings`, no `package.json`. Preencha `BETTER_AUTH_SECRET` e, para o login funcionar, `RESEND_API_KEY` e `EMAIL_FROM`.

<aside>

**Atenção: publicação automática.** O botão liga o Workers Builds ao seu repositório: **todo push na `main` publica o app**, inclusive PRs do Dependabot depois de mesclados. Só mescle com o CI verde. O CI do GitHub Actions, sozinho, nunca publica.

</aside>

Não esqueça de trocar `url` em `src/config/app.ts` antes de clicar no botão.

## Depois do deploy

- Abra a URL publicada e faça um login de teste.
- Confira os logs no painel da Cloudflare (a observabilidade já está ligada) ou ao vivo com `npx wrangler tail`.
- Login social: cadastre `https://<domínio>/api/auth/callback/google` (e `/github`) nos apps OAuth.
- As demos `/demo/*` só existem no `npm run dev`; na versão publicada elas não aparecem.
